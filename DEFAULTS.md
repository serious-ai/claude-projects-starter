# Your standing defaults

The rules you want in every project, written once. When you set up a new project, Claude merges these into its `AGENTS.md` before any thread starts, so you stop retyping the same guardrails and no project starts without them. Keep this file in your own copy of the starter, replace each line in [brackets] with your own, and delete what doesn't apply to you.

Added November 23, 2026, after we started briefing every new project from this kit on day one.

## Who it's for

- Every goal names what would prove it wrong: [the number or result that would show the goal was the wrong one].

## Where the work happens

- [The page, doc or folder] is the source of truth for each project. Log every change and every result there.
- Anything that drafts what a person will receive runs as a thread on your own computer, where your hooks and checks run. Research on public data can run in the cloud.

## How a thread checks its own work

- Every claim traces to a source, a URL and the date read, on the same line.
- A repo the project creates or changes runs its tests in a GitHub check on every pull request, and a pull request merges once that check passes. Hooks don't run in cloud threads, and a GitHub check runs wherever the thread ran.

## When something is missing

- Find facts before asking: your files, your notes, your mail, the web. Ask only what is yours to decide.
- Questions to you come numbered, each with the recommended answer under it.

## What needs my go-ahead

- Every email, post and publish. Threads write drafts only.
- [Anyone the project should not contact yet, and until when.]

## Guardrails

- No patient health information or client records in any cloud thread.
- A rule that has to hold every time (a banned word, a format, a file location) becomes a check, not another line of instructions.
